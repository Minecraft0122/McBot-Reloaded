使用 Java 25 时必须满足表中的最低加载器版本；更旧的加载器可能在 McBot 初始化前就因 ASM/Mixin 无法识别 Java 25 类文件而停止。

四个正式 JAR 由同一个标签自动构建并发布到 [GitHub Releases](https://github.com/Minecraft0122/McBot-Reloaded/releases/latest)。

1.20.1 的最低 Java 与字节码目标仍是 17，1.21.1 的最低 Java 与字节码目标仍是 21。持续集成另外用 Temurin 21、25 启动真实专用服务器，检查 McBot 的运行时版本日志、完整启动和正常关服。Java 18—20、22—24 未纳入同等级持续验证。

## 历史开发实现

- 1.14.4、1.15.2、1.17.1、1.20.2：在 `fabric-dev`、`forge-dev` 中保留开发实现。
- `fabric-config-hocon`、`koishi-backend`：实验性实现，不等同于稳定客户端。
- 1.21.5、1.21.7 及更新版本：当前没有可验证的正式构建，不能只修改模组元数据后使用。

## 兼容性含义

“已通过完整构建”表示源码编译、测试、资源处理、重映射和最终 JAR 生成成功。“服务端运行测试”还表示对应 Java 与加载器组合可以启动到 `Done`、日志确认 McBot 已加载，并可通过 `stop` 正常退出；两者都不表示与任意其他模组组合必然兼容。

反馈兼容性问题时必须提供：

- Minecraft 版本；
- Java 完整版本；
- Fabric/Forge/NeoForge 及其版本；
- McBot 文件名和版本；
- OneBot 实现及版本；
- 完整服务端日志；
- 最小复现步骤和已脱敏配置。

不同 Minecraft 版本、加载器和 Java 主版本的 JAR 不得混用。分支源码只能代表维护入口，不能代替 Release 中经过自动发布流程生成的正式产物。
